# 节点池

本文档介绍 Paily 主服务的节点池：节点如何入库、如何去重、如何与来源关联，以及存活状态如何判定。

## 工作流程

Paily Fetch 每轮抓取结束后，把每个来源解析出的节点上报给 Paily 主服务。Paily 主服务逐个处理：

1. 依据节点属性计算稳定哈希，找出已存在的节点。
2. 更新已有节点的内容，或创建新节点。
3. 维护节点与来源的对应关系。
4. 清理该来源中已经消失的节点关联，并删除不再被任何来源引用的节点。

Paily 测活后端随后从节点池拉取节点进行测活。测活结果由 Paily 主服务写入历史和评分，不直接修改节点与来源的对应关系。

## 节点去重

节点池中的每个节点代表一个去重后的代理实体。Paily 主服务使用「协议 + 地址 + 端口 + 密码」计算稳定哈希，因此同一节点即使出现在多个来源中，也只会保存一份。

新抓取到的节点初始为未存活、评分为 0，需经过 Paily 测活后端初筛后才会参与分发。已有节点在更新内容时会保留其测活历史，因此延迟等历史数据不会因为来源重新抓取而丢失。

## 节点与来源的关联

节点与来源是多对多关系：

- 一个节点可以来自多个来源。
- 一个来源可以提供多个节点。

当某个来源的抓取结果显示某节点已消失时，Paily 主服务只删除该来源与该节点的关联。若该节点仍被其他来源引用，则继续保留；若不再被任何来源引用，则连同其测活历史和评分一起删除。

对于抓取失败的来源，Paily 主服务会保留其原有节点，直到该来源被判定为失效后才清理关联。这样可避免一次临时抓取失败就丢失整个来源的节点。

## 节点字段

| 字段 | 说明 |
| --- | --- |
| `hash` | 用于去重的稳定哈希。 |
| `server` | 节点地址。 |
| `protocol` | 节点协议。 |
| `password` | 节点的主要认证凭据。 |
| `region` | 出口地区，由测活结果的复筛阶段给出。 |
| `alive` | 是否存活，由初筛结果决定。 |
| `score` | 节点综合评分，由复筛结果计算。 |
| `sources` | 与该节点关联的来源列表。 |

节点同时保存原始配置，便于查看、复现和转换为各种订阅格式。

## 入池闸门

免费来源每一轮都会重新发布同一批死端点。没有闸门时池子会无界增长，测活预算大半花在
反复探测从未成功过的节点上。抓取结果在写入前经过四道过滤：

| 关卡 | 规则 | 配置键 |
| --- | --- | --- |
| 批内去重 | 同一批里 hash 相同的只保留第一条 | — |
| 已归档拦截 | 命中 `archived_at IS NOT NULL` 的 hash 直接丢弃 | — |
| 端点上限 | 同一 `server:port` 最多准入 N 个（不同 UUID 指向同一 CDN 地址很常见） | `ingress_max_per_endpoint`（默认 3） |
| 零产出协议配额 | `ss` / `ssr` / `hysteria2` / `socks5` / `tuic` / `anytls` / `wireguard` 各限 N 个 | `ingress_zero_yield_quota`（默认 20） |

已存在于池中的节点属于「刷新」，不受配额限制；配额只约束新增。被过滤的数量会以
`node upsert: ingress gate filtered` 日志输出，按来源分布就能看出哪个源在灌垃圾。

> 零产出协议**不是永久拒绝**：真正的协议复活仍能通过剩余配额进入，只是无法靠数量淹没池子。

## 软归档

从未通过任何一次测活的节点，在入池超过 `node_never_alive_retention_days` 天后被标记
`archived_at`，不再进入测活候选。

**为什么是归档而不是删除**：来源每轮都会重新发布同一批死节点。硬删除之后，下一轮抓取
会把它们当作新节点重新拉回并刷新 `created_at`，形成「删了又回来」的死循环。保留行可以让
唯一 hash 索引继续拦截回流，而且零成本。归档会触发一次缓存重建，避免分发继续使用刚退休的节点。

## 存活判定

存活状态由初筛结果决定，与评分相互独立。

Paily 主服务在 `node_alive_check_window_minutes` 窗口内，查询每个「节点 + 测活后端 tag」的最新一条初筛结果：

- 只要有一个 tag 的最新结果为可达，节点即为存活。
- 若没有任何成功的初筛结果，节点即为未存活。

由于不同测活后端可以位于不同网络环境，同一节点在不同 tag 下的可用性可能不同。分发时可以指定 tag，只使用对应测活视角的初筛结果；不指定 tag 时，则使用各视角的并集。

## 管理界面操作

管理界面的「节点管理」页面提供以下操作：

- 按存活状态、地区、协议、地址、来源、评分区间、流媒体解锁能力和测活后端 tag 筛选节点。
- 使用表达式进行高级搜索。
- 查看节点详情、原始配置、关联来源，以及按 tag 的初筛与复筛历史。
- 删除节点。
